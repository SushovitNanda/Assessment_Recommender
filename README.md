# SHL Assessment Recommender (RAG)

Conversational API that helps hiring managers shortlist **SHL Individual Test Solutions** from a local catalog. The backend combines **retrieval-augmented generation (RAG)** with a **slot-based dialogue policy** so recommendations stay grounded in catalog data and URLs are never invented by the model.

## What this RAG stack does

1. **Catalog** — Assessments live in `data/catalog.json`. Each row is validated, enriched with derived fields (`test_type`, `all_test_types`, `embedding_text`, duration, etc.).
2. **Embeddings & index** — **FastEmbed** [`TextEmbedding`](https://qdrant.github.io/fastembed/) with **`BAAI/bge-small-en-v1.5`** (ONNX): catalog rows use `passage_embed`, search queries use `query_embed`. Vectors are stored in a **FAISS** `IndexFlatIP` index (cosine similarity on L2-normalized vectors). After changing the embedding model, delete `data/faiss.index` / `data/faiss_meta.pkl` and run `python build_index.py`.
3. **Per-request retrieval** — The service expands the user context into several search queries, runs FAISS search, optionally applies soft metadata filters (duration, remote, test categories, job level), merges and deduplicates candidates.
4. **LLM** — **`google.generativeai`** (**Gemini**; model id defaults to `gemini-3.1-flash-lite`, overridable with `GEMINI_MODEL`) powers structured **extraction** from the transcript, the main **recommend / clarify / compare** JSON reply, and grounded **compare** narratives when users name assessments.

The API is **stateless**: every `POST /chat` must send the **full** `messages` history.

## Requirements

- Python 3.11+ (3.13 supported with pinned deps in `requirements.txt`)
- `GEMINI_API_KEY` in a project file named **`env`** (dotenv format), e.g. `GEMINI_API_KEY=...`
- Optional: `GEMINI_MODEL=<model-id>` to override the default chat model

## Quick start

```bash
pip install -r requirements.txt
# Ensure data/catalog.json exists; pre-build index for fast cold start:
python build_index.py
uvicorn main:app --host 0.0.0.0 --port 8000
```

Health check: `GET http://127.0.0.1:8000/health`

## Python modules (short)

| File | Role |
|------|------|
| `main.py` | FastAPI app: lifespan loads catalog, FAISS, Gemini config; exposes `/health` and `/chat`. |
| `schemas.py` | Pydantic models: `ChatRequest`, `ChatResponse`, `Message`, `Recommendation`, `HealthResponse`. |
| `catalog.py` | Load/filter catalog JSON; map SHL `keys` to type codes (`K, A, P, …, S`); build `embedding_text`; name index helpers. |
| `retriever.py` | FAISS build/load, vector search, metadata filters, hybrid `retrieve()`, name lookup and `resolve_catalog_name()` for compare/typos. |
| `agent.py` | Intent guards, **extract** LLM call + regex normalization, slot gating, retrieval orchestration, main JSON LLM call, URL-safe recommendation validation, compare handler. |
| `prompts.py` | `SYSTEM_PROMPT`, `EXTRACTION_PROMPT`, `RERANK_PROMPT`, `COMPARE_PROMPT` templates. |
| `build_index.py` | Offline script: writes `data/faiss.index` and `data/faiss_meta.pkl`. |
| `print_chat.py` | CLI: POST `/chat` and print full JSON (avoids PowerShell truncation). |
| `evaluate.py` | Replay `data/traces/` against `/chat`; offline retrieval metrics; grounding & `data/evaluation_rubric.json` (built-in default; optional local `instructions.json` override). |

## Evaluation (`evaluate.py`)

Bootstraps layout + sample traces + **`data/evaluation_rubric.json`** (from the **built-in rubric** in `evaluate.py`; if **`instructions.json`** exists locally, its `scoring_rubric` overrides when you run `--init` or `--sync-rubric`):

```bash
python evaluate.py --init
python evaluate.py --base-url http://127.0.0.1:8000
```

**Metrics (summary JSON → `data/eval_results.json`):**

- **Hard checks** — every turn validates **`ChatResponse`** (`reply`, `recommendations`, `end_of_conversation`), SHL URLs, catalog-canonical URLs for recommended names, **≤ 8 scripted user turns**, optional behavior probes (vague first-turn empty recs, off-topic refusal).
- **Recommendation relevance** — **Recall@10** vs `expected_assessments` on final API recommendations.
- **Retrieval quality (offline)** — hybrid **`retrieve()`** Recall@10 / @20 using trace **`facts`** (mirrors agent filters).
- **Groundedness / accuracy** — URL match to `catalog.json`; **retrieval alignment**: share of API picks that appear in top-20 retrieved names.
- **Effectiveness** — fixed-weight composite of relevance + retrieval recall + retrieval alignment (`aggregate.mean_effectiveness_composite`).

Add official SHL trace JSON files under **`data/traces/`** alongside the seeded examples.

## API endpoints

### `GET /health`

**Response** (`200`)

```json
{ "status": "ok" }
```

Use for readiness / cold-start probing.

### `POST /chat`

**Headers:** `Content-Type: application/json; charset=utf-8`

**Request body**

| Field | Type | Rules |
|-------|------|--------|
| `messages` | array | Non-empty. Each item: `role` ∈ `user` \| `assistant`, `content` string. **Last** message must be `user`. Max 16 messages enforced. |

**Example**

```json
{
  "messages": [
    { "role": "user", "content": "We need to screen entry-level contact centre agents in the UK, English only, max 25 minutes, remote." }
  ]
}
```

**Response** (`200`) — shape is fixed for clients

| Field | Type | Description |
|-------|------|-------------|
| `reply` | string | Natural language answer (clarification, rationale, comparison, etc.). |
| `recommendations` | array | `[]` when clarifying, refusing, or comparing. Otherwise 1–10 items with catalog-verified data. |
| `recommendations[].name` | string | Exact catalog assessment name. |
| `recommendations[].url` | string | URL taken from catalog (never from raw LLM output). |
| `recommendations[].test_type` | string | All applicable SHL type codes for that row, comma-separated (e.g. `A, K, S`). `S` = Simulations. |
| `end_of_conversation` | boolean | `true` only when the agent treats the task as finished. |

**Example (abbreviated)**

```json
{
  "reply": "…",
  "recommendations": [
    {
      "name": "Customer Service Phone Simulation",
      "url": "https://www.shl.com/products/...",
      "test_type": "S"
    }
  ],
  "end_of_conversation": false
}
```

## Errors and HTTP status codes

| Situation | Typical status | What you see |
|-----------|----------------|--------------|
| Empty `messages` | **422** | Pydantic / FastAPI validation or `"messages list cannot be empty."` |
| Last message not `user` | **422** | `"Last message in history must be from 'user'."` |
| More than 16 messages | **422** | `"Conversation history exceeds maximum length."` |
| Unhandled server exception | **500** | JSON body still shaped like `ChatResponse` with a generic `reply` and empty `recommendations` (see `main.py` handler). |
| Invalid JSON body | **422** | Validation error detail from FastAPI. |

**Application-level failures (still often `200`):**

- **LLM quota / timeout** — The agent may fall back to top retrieved catalog rows when the main completion fails, or return clarifications if slots are incomplete. Check logs for Gemini errors (e.g. `429`).
- **Missing API key at startup** — `GEMINI_API_KEY` not set in `env` → startup fails when creating the client.

## Troubleshooting

| Symptom | Things to check |
|---------|------------------|
| Service won’t start | `env` file present with `GEMINI_API_KEY`; `data/catalog.json` exists; run from project root so paths resolve. |
| Port already in use | Another process on `8000` — change port: `uvicorn main:app --port 8001` or free the port (OS-specific). |
| Empty or odd recommendations | Ensure the user message (across history) fills **role, seniority, what to measure, language, logistics**; see `agent.py` slot helpers. |
| Compare says product “not in catalog” | Names must resolve to catalog rows; optional suffixes like ` (New)` and trailing `?` are handled in `resolve_catalog_name`. Restart after pulling code changes. |
| Stale retrieval / wrong matches after a model swap | After large `catalog.json` edits or changing the FastEmbed model in `retriever.py`, run `python build_index.py` (or delete `data/faiss.index` and `data/faiss_meta.pkl` and restart). |
| PowerShell truncates JSON | Use `python print_chat.py -m "your message"` or `ConvertTo-Json -Depth 10` and inspect `reply` / `recommendations` fields. |
| Gemini **429** | Billing/quota on Google AI Studio; try later, another key, or set `GEMINI_MODEL` to an available SKU. |
